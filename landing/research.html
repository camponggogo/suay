    One hundred ports is not faster than two

    Extra gateways on their own ports, an asyncio round-robin dispatcher, and a driver that split clients across ports. The second port paid for itself; the rest did not. Eight ports measured worse than two, and the first error appeared at C=64. Extrapolated to 100 ports: 4.4 GiB of gateway memory, 100 SQLite writers, the same 24–29 req/s.

    Found the ceiling: 60 ms of event loop per request

    A layer probe at C=16 isolated the cost. The raw loop served 58.7–71.2 req/s, the completion path 15.7 — and the mock upstream used 0.8 % CPU, so the network and the backend were innocent. Two workers, re-tested after the caches landed, added 48–58 % with zero errors.

    What N workers do to the rest of the system

    Ten fresh connections to the two-worker gateway: nine read events=60, requests=30, one read events=2, requests=1. Counters and the event stream live in process memory, so they divide by N; budgets, audit and liveness are shared and correct. Revocation lags at most the 2 s cache per worker.

    PostgreSQL on the hot path: 4.5 req/s

    The adapter, the pool and the compose service were built and measured. But the control plane's users and audit tables still live in SQLite, and that file is protected — so the schema split, and the gateway failed under load. Reverted to SQLite with one writer; the adapter stays in the tree for the day the migration is possible.

    The missing cache: five seconds of node list

    Dispatch looked up the live machines on every request. Caching that list for five seconds turned the same workload from 4.9 into 15.0 req/s at C=8 — a 3× gain from one line of state, and the reason the two-worker re-test finally behaved.

    SQLite versus PostgreSQL under writers

    Thirty-two writers: SQLite keeps 19 % more throughput but its p95 rises to 740 ms and its worst request takes nine seconds. PostgreSQL trades throughput for a 36 % lower p95 and a seven-times lower maximum — the right choice for a multi-worker future, just not sufficient on its own.

    Denoising: worth 1.15 dB, not worth a learned gate

    Four methods on 963 samples. Savitzky–Golay won at +1.15 dB; a learned gate in the DeepFilterNet style lost 0.19 dB. The variance was queue ramp, not noise — which is why the paper plots raw values with bootstrap intervals and uses smoothing only for display.

    The CPU sweep went the wrong way

    We expected more CPU per machine to help. Throughput plateaued at 10 % of a core and fell 25 % at 80 %, because 50 containers × 0.8 cores is 40 cores on an 8-vCPU host. At 1 % the fleet fell apart: 28–39 of 50 machines stayed live and dispatch rose to 133 ms.

    157× came from not computing twice

    Content-addressed 256-token blocks, a registry of which machine holds which block, and longest-prefix routing. An 8 000-token document with 90 % reuse went from 111.4 s to 0.71 s to first token. The tail did not move at all — the cache fixes the median, not p95.

    Splitting the planes: 44 → 161 req/s

    Heartbeats moved out of the gateway into a node plane: state in a dictionary, one batched flush every ten seconds, sharded by crc32. Heartbeat throughput tripled, dispatch p50 fell from 67 ms to 3.1 ms, and single-request latency halved.

    Fifty machines, 48 000 requests, zero errors

    The first honest load test. Throughput sat at 12 req/s while latency grew linearly; at C=50, 96.5 % of the response time was queueing above a 174 ms service floor. Little's law held within 2.15 % and per-machine fairness was tight — the queue was in one process, not in the fleet.

READ THIS WITH THE NUMBERS

What the log is not

01

Mock backend.

The harness isolates the control plane. With a real 0.5B model a machine serves 0.14 req/s, so fifty machines deliver about 7 req/s and the gateway ceiling stops binding.

02

One host, ±15 %.

Fifty-three containers, Docker Desktop and the load generator share eight vCPUs. Single runs are indicative; the repository keeps the JSON per run so the spread is visible.

03

Simulated cache.

Prefix reuse is modelled at the routing layer. Tensors are not materialised, so the 157× is a routing result, not a memory-bandwidth claim.

A SHARED STARTING POINT

Measure it.
Then improve it.

The most useful artefact here is not the code. It is the list of things that looked like a good idea and measured badly — that is the part which saves the next team a week.

Use it. Inspect it. Improve it. Share what you learn.
