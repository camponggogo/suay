SUAY เป็นโครงการโอเพนซอร์สสำหรับทดลองแบ่งปันทรัพยากรคอมพิวเตอร์เพื่อรัน AI ภายในองค์กร เริ่มจากเครื่องที่มีอยู่ พร้อมระบบบัญชี สิทธิ์ และ API key สำหรับทีมพัฒนา

ดูซอร์สโค้ดและกด Star ↗เริ่มต้นใช้งาน ↗

SUAY ทำงานอย่างไร?

ระบบควบคุมมี dashboard จัดการบัญชี สิทธิ์ตาม zone และโหนด API key แบบหมดอายุได้ งบจำนวนคำขอ และ audit log ส่วน inference gateway ส่งคำขอไปยัง backend ที่ผู้ดูแลกำหนด โมเดลต้องอยู่ในรายการที่อนุมัติ

ส่วนแบ่งโมเดลด้วย Petals เป็นการทดลองใน LAN อีกชุดหนึ่ง ยังไม่ได้เชื่อมอัตโนมัติกับ gateway และคำสั่ง native worker ยังไม่ถูกนำไปทำงานจริง อ่านสถาปัตยกรรมระบบ

เหมาะกับองค์กรแบบไหน?

เหมาะกับทีม IT ทีมพัฒนาระบบภายใน และห้องทดลองที่ต้องการประเมิน local AI ก่อนเพิ่มงบ GPU หรือ cloud ควรวัดหน่วยความจำ ความเร็ว เครือข่าย ค่าไฟ และเวลาบริหารจริง ไม่มีการรับประกันความประหยัดหรือประสิทธิภาพล่วงหน้า

PROJECT FACTS / FAQ

คำถามเกี่ยวกับการแชร์ทรัพยากรเพื่อรัน AI

SUAY คืออะไร?

SUAY เป็นโครงการโอเพนซอร์สสำหรับแบ่งปันทรัพยากรเพื่อรัน AI ภายในองค์กร มีระบบบัญชีและ API gateway รุ่นทดลอง และมีระบบแบ่ง model blocks ด้วย Petals ใน LAN ที่แยกจากกัน

คอมพิวเตอร์เก่าสามารถร่วมกันรัน AI ได้หรือไม่?

ทำได้กับเครื่องที่ runtime หน่วยความจำ และเครือข่ายรองรับงานนั้น ต้องทดสอบบนฮาร์ดแวร์จริง SUAY ไม่รับประกันว่าทุกเครื่องเก่าจะรันได้หรือเพิ่มความเร็วได้

SUAY รวม RAM ของทุกเครื่องเป็นก้อนเดียวหรือไม่?

ไม่ใช่ระบบรวมหน่วยความจำทั่วไป ส่วนทดลอง Petals แบ่ง model blocks ที่รองรับไปยัง worker การกระจายคำขอไปหลายเครื่องต่างจากการแบ่งโมเดลเดียวข้ามเครื่อง

ตอนนี้ใช้อะไรได้แล้ว?

มีบัญชีผู้ใช้ สิทธิ์ตาม zone และโหนด API key ที่หมดอายุได้ งบจำนวนคำขอ audit log และ proxy ไปยัง backend ที่ผู้ดูแลอนุมัติ คำสั่ง worker ยังรอดำเนินการเพราะยังไม่มี native transport

รองรับ Windows, macOS, Linux และ Android หรือยัง?

ส่วนควบคุม Python ทดลองได้ในสภาพแวดล้อมที่ติดตั้ง dependencies ได้ ส่วน compute ต้องทดสอบ Petals ให้ตรงระบบ ยังไม่มีตัวติดตั้ง native service สำหรับ Windows macOS และ Linux และยังไม่เปิดใช้ Android เป็น compute worker

องค์กรใช้ SUAY ฟรีได้หรือไม่?

โค้ด SUAY ใช้ MIT license ซึ่งอนุญาตให้ใช้เชิงพาณิชย์ตามเงื่อนไขของ license แต่โมเดลและ dependencies ใช้เงื่อนไขของตนเอง เช่น BLOOM ใช้ BigScience RAIL จึงต้องตรวจ license ก่อนใช้งาน

ทีมพัฒนาเรียกใช้ผ่าน API ได้หรือไม่?

ได้ ผู้ดูแลต้องตั้ง inference backend ที่อนุมัติก่อน แล้วออก API key แบบกำหนดสิทธิ์เพื่อเรียก chat completions แบบไม่ streaming งบใช้งานนับจำนวนคำขอและแสดง model tokens ที่ backend รายงานแยกกัน

พร้อมใช้งาน production หรือยัง?

ยังเป็นรุ่นทดลอง ระบบยืนยันตัว worker SSO/MFA การ deploy ที่เซ็นชื่อ และการย้ายโมเดลอัตโนมัติยังไม่สมบูรณ์ ควรทดสอบบนเครือข่ายที่เชื่อถือได้ก่อน
